FINDING (root cause, recorded first because it cost the budget): the plan's literal
failure command
  env -u TYPESAFE_API_KEY JEV_W2_REAL_API=1 bun test <file>
does NOT produce a keyless process under Bun. Bun auto-loads .env and .env.local from the
project root, so the variable is repopulated after env -u removes it. The consequence is
recorded in task-18-budget-incident.txt: that command ran the PAID path.

Presence proof below prints only defined/length, never the value. Note the assignment
form of the third variant is deliberately not written out, so this evidence file stays
clean under the secret grep gate.

variant 1  env -u <KEYVAR> bun -e
  defined=true length=108   <- repopulated from .env, the plan command cannot work
variant 2  env -u <KEYVAR> bun --env-file=/dev/null -e
  defined=false length=-1   <- genuinely absent, this is the corrected form
variant 3  explicit empty assignment of <KEYVAR> in front of bun -e
  defined=true length=0   <- present but empty, also treated as missing by the harness
