WHY IT IS ENOUGH
  The three claims the plan actually cares about are each backed by a measurement rather than an
  assumption. The one-request-per-call claim is measured twice, once against a server whose own
  counter is independent of the client counter. The ceiling is shown to ABORT with a named error
  before the next call reaches the wire, at the real 18/19 boundary in a committed test and again
  in the sandbox at a 2/3 boundary. The resolved model is captured per call, not once, so a mid
  run alias float would have been visible. The score is reported with no floor asserted anywhere,
  proven by a complete inventory of every expect() in the owned files (task-18-no-minimum-score.txt).
  The budget is now bounded across processes, not just within one, which is strictly stronger
  than what the plan asked for and is the direct remedy for how the spend happened.

WHAT WAS OMITTED

  evidence file. Credential presence is recorded only as a boolean and a length. The SDK logger
  is the silent logger and logLevel is "error", so no request or response bodies were captured.
  The assignment form of the empty-variable invocation is deliberately not written out in
  task-18-missing-key.txt so the evidence directory stays clean under the secret grep gate; the
  same proof is given in the --env-file=/dev/null form instead.
  Billing units are NOT claimed. Request count and token counts are measured; no pricing source
  was consulted, so the recorded claim is narrowed to "1 HTTP request and the recorded token
  counts per three-question call, billing units unverified".
  The paid run was NOT repeated, so there is no variance estimate for the probabilities. That is
  a deliberate consequence of the budget, not an oversight.
