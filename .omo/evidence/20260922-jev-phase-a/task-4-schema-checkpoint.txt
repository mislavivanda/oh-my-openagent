## 2. INVESTIGATION FINDING: the stated premise is factually mistaken

There is no "paste your key" installer flow in this repository for any provider, so there is
no such flow for the jev config to conform to. Verified by two explore agents plus direct
checks by the orchestrator:

- Verification command: grep -rn "p\.password\|p\.text(" packages/omo-opencode/src/cli/
  Result: no matches, empty output. The installer never captures a free-text secret from the
  user for any provider.
- Provider questions are yes/no p.select subscription questions, not text entry:
  packages/omo-opencode/src/cli/tui-install-prompts.ts:87-206
- After the interview the installer only PRINTS an instruction and collects nothing:
  packages/omo-opencode/src/cli/tui-installer.ts:194-207 prints "Run opencode auth login".
- Real credential capture and storage is owned by opencode itself, in its own auth file under
  ~/.local/share/opencode/auth.json. Our plugin reads that file only to learn whether a
  provider is oauth or api, and deliberately discards the secret values:
  packages/omo-opencode/src/shared/opencode-provider-auth.ts:55-83
- Delegating to "opencode auth login" is impossible in principle: that command only knows the
  model providers OpenCode supports, and Jev is not a model provider. It is a decision-layer
  service.

## 3. CONVENTION EVIDENCE: env-only is the established pattern for feature-level secrets

Every non-model-provider secret in this codebase is read from the environment, never from
config and never from an installer prompt:

- EXA_API_KEY and TAVILY_API_KEY in packages/omo-opencode/src/mcp/websearch.ts:16-18,37
- CONTEXT7_API_KEY in packages/omo-opencode/src/mcp/context7.ts:9-17
- POSTHOG_API_KEY in packages/omo-opencode/src/shared/posthog.ts:126-139
- OPENCODE_SERVER_PASSWORD in packages/omo-opencode/src/shared/opencode-server-auth.ts:10-11

The committed schema conforms to that convention. packages/omo-opencode/src/config/schema/jev.ts
documents on the backend field that the key is read ONLY from the TYPESAFE_API_KEY environment
variable and never from this config, and the schema carries no credential-bearing field at all
(fields are: enabled, backend, model, timeout_ms, wires).
