2. WHY THE AMBIENT ENV VAR IS EXCLUDED

OPENCODE_SERVER_PASSWORD is exported into the agent's shell by this repo's own development
setup (root AGENTS.md documents .env, script/agent/setup.sh, and script/agent/qa-sandbox.sh;
.env.example lists the variable). When it is set, the tmux pane spawner forwards it as
`-e OPENCODE_SERVER_PASSWORD=...` to `tmux split-window`, which adds two argv entries that the
tmux test fixtures do not expect. That is a property of the developer's shell, not of the
repository, so it is excluded from the canonical command.

Isolation proof, both runs in THIS worktree, same tree, no edits between them:
  with the variable set     task-1-baseline-bun-test.txt      exit=1   22 fail
  with the variable removed task-1-canonical-baseline.txt     exit=1    7 fail
The 15-line difference is 14 distinct tmux tests and nothing else (one name is reported twice):
all of spawnTmuxPane, spawnTmuxWindow, replaceTmuxPane runner integration, and one
team-layout-tmux topology test. Scoped confirmation:
  env -u OPENCODE_SERVER_PASSWORD -u TMUX -u CMUX_SOCKET_PATH bun test packages/tmux-core/src/tmux-utils
    -> exit=0, 85 pass / 0 fail
No tmux test is in the accepted-failure list below, because with the variable removed they pass.

4. ONE QUARANTINED FLAKE, DELIBERATELY EXCLUDED FROM THE LIST

    pollForCompletion > does not check completion during stabilization period after first meaningful work

The first canonical run produced 8 failures, not 7. The extra one was investigated rather than
accepted. A 3-run stability study (details in task-1-canonical-baseline-flake-analysis.txt) showed
it failing in 1 of 3 full runs and passing 6 of 6 isolated runs. It is a wall-clock race inside the
test's own stabilization-window assumption, exposed under full-suite CPU contention. It is excluded
from task-1-canonical-baseline-failures.txt on purpose: a nondeterministic entry would make F2's
diff raise false alarms in both directions. If a future run shows ONLY this test newly failing,
re-run that file in isolation before calling it a regression.


5. THE EXACT NORMALIZATION COMMAND (reproduce byte-for-byte)

task-1-canonical-baseline-failures.txt was produced from the raw capture by:

    grep -E '^\(fail\)' .omo/evidence/20260924-jev-w1/task-1-canonical-baseline.txt \
      | sed -E 's/\x1B\[[0-9;]*[a-zA-Z]//g; s/^\(fail\) //; s/ \[[0-9.]+m?s\]$//' \
      | LC_ALL=C sort

It strips ANSI escapes, strips the leading "(fail) " marker, strips the trailing "[12.34ms]"
timing suffix, and sorts under LC_ALL=C so ordering never depends on locale. Verified: re-running
the command against the recorded raw capture reproduces the file byte-for-byte,
sha256 e58c7b4ab1d56299fd92dd3a115e1029d5bb81ff5aed86435e63e773af508011.
F2 must apply this identical pipeline to its own run before diffing, or the comparison is invalid.
